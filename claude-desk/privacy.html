Privacy Policy

Last updated: 2026-06-07

claude-desk itself collects nothing and makes no network requests of its own. It is a local Mac app that spawns the claude CLI you already have installed and renders its output.

What stays on your Mac

  • Project list, pane layout, and UI preferences — stored in standard NSUserDefaults for the app.
  • Per-project session transcripts (every message, every tool call, every response) — stored as .jsonl files in ~/Library/Application Support/claude-desk/sessions/.
  • Pasted images and other attachments — stored in ~/Library/Application Support/claude-desk/attachments/.

None of this is ever uploaded by claude-desk. You can inspect, edit, copy, or delete any of it with Finder.

What leaves your Mac (via the Claude CLI)

When you send a message, claude-desk hands it to the claude CLI as a subprocess. The CLI then makes an HTTPS request to Anthropic's API on your behalf, using your Anthropic API key (or your claude.ai session). The prompt, the relevant conversation history, attached files, and tool-call results travel to Anthropic. claude-desk never sees or stores your API credentials — that's the CLI's job.

How Anthropic handles that data is governed by Anthropic's Privacy Policy and the terms of the API plan or claude.ai account you're authenticated under. claude-desk has no influence over that path — it only assembles and renders what the CLI processes.

MCP servers you configure

If you've configured MCP servers (in the Claude CLI's own config), claude-desk relays JSON-RPC over a UNIX socket to a small bundled shell script. The script's only job is to forward each line back to the app so we can show the permission dialog. The script runs locally; no data goes off-device through this path. Whether the MCP server itself sends data off-device depends on the server — those are configured by you, not by claude-desk.

Analytics, ads, third-party SDKs

  • No analytics framework is linked into the app (no Sentry, Mixpanel, Crashlytics, Firebase, etc.).
  • No advertising framework.
  • No third-party SDK of any kind.
  • No background uploads, crash reports, or update pings to anything operated by the developer.

Code signing and Gatekeeper

The app is signed with the developer's Apple Developer ID so Gatekeeper accepts it. The signature does not give the developer visibility into who is running the app.

Changes to this policy

If we ever change what the app does with your data, this page will be updated and the "Last updated" date at the top will reflect that. Material changes will also be noted in the app's release notes.
